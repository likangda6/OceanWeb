# 需求规格说明书

**项目名称**：基于 Spring Boot 与 Vue.js 的智能海洋生物管理平台设计与实现
**文档版本**：V1.0
**编写日期**：2026-09-09

---

## 一、引言

### 1.1 编写目的
本需求规格说明书旨在明确"智能海洋生物管理平台"的功能需求、非功能需求及接口约束，作为系统设计、开发、测试与验收的依据。读者对象包括：项目经理、后端开发工程师、前端开发工程师、测试工程师、运维人员及项目验收方。

### 1.2 项目背景
海洋生物科普教育在生态保护与科学传播中占有重要地位，传统海洋科普平台多采用静态图文展示，存在物种检索困难、缺乏智能问答、视频资源分散、管理手段落后等问题。本项目融合 **通义千问 VL 视觉大模型**、**DeepSeek 流式对话**、**阿里云 VOD 视频点播** 与 **Spring Boot + Vue.js** 全栈技术，构建一个集物种管理、智能识别、AI 对话、科普视频、海洋图谱可视化于一体的智能海洋生物管理平台。

### 1.3 项目范围
平台覆盖以下业务域：
- 用户注册、登录与权限管理
- 海洋生物（鱼类、鲸类、无脊椎动物）物种管理与分类检索
- 基于视觉大模型的智能海洋生物图像识别
- 基于 LLM 的流式 AI 对话与多模态问答
- 科普视频点播与管理后台
- 海洋生物分类图谱与统计可视化
- 海洋主题互动小游戏

### 1.4 术语与缩写
| 术语 | 含义 |
|---|---|
| JWT | JSON Web Token，用于无状态身份认证 |
| VOD | Video on Demand，阿里云视频点播服务 |
| OSS | Object Storage Service，阿里云对象存储 |
| MinIO | 兼容 S3 协议的开源对象存储 |
| SSE | Server-Sent Events，服务端推送流式数据 |

| RBAC | Role-Based Access Control，基于角色的访问控制 |
| 纲/目/科 | 生物分类学层级（Class / Order / Family） |

## 二、总体描述

### 2.1 用户类别与角色

| 角色 | 标识 | 权限范围 |
|---|---|---|
| 访客 | 未登录用户 | 仅可访问欢迎页、登录、注册页 |
| 普通用户 | `ROLE_USER` | 全部前台功能：物种检索、AI 对话、视频观看、图谱浏览、游戏互动 |
| 管理员 | `ROLE_ADMIN` | 普通用户全部权限 + 管理后台：物种 CRUD、视频管理、监控仪表盘 |

### 2.2 运行环境
- **后端**：JDK 17、Spring Boot 2.6.7、Tomcat 9（内嵌）、MySQL 8、MongoDB 5、Redis（可选）
- **前端**：Vue 2.6+、Vue Router 3、Element UI、Vite 构建、ECharts 5
- **中间件/三方服务**：MinIO 8.5.3、阿里云 VOD、阿里云 OSS、通义千问 DashScope、DeepSeek API
- **客户端**：现代浏览器（Chrome / Edge / Firefox 最新版），支持 ES6 与 HTML5

### 2.3 设计约束
1. JDK 版本固定为 17，编译目标级别与 JDK 一致
2. 前端使用 Vue 单文件组件（.vue），禁用 JSP
3. 除登录、注册、Vue 入口、API 文档、静态资源、物种公开检索、AI 识别、视频列表外的接口均需认证
4. `/api/admin/**` 接口强制要求 `ROLE_ADMIN` 权限
5. JWT 密钥须硬编码静态值，避免重启导致已签发 token 失效
6. JWT role claims 不被信任，每次请求须从数据库实时查询用户角色
7. 密码使用 BCrypt 加密存储
8. Knife4j 兼容性要求 `spring.mvc.pathmatch.matching-strategy: ant_path_matcher`
9. MinIO bucket `knowledge-base-files` 须配置公共读策略

### 2.4 假设与依赖
1. 部署环境预装 MySQL 8、MongoDB、MinIO 并完成初始化
2. 阿里云 VOD、OSS、通义千问 DashScope、DeepSeek 账号与 API Key 已配置
3. 数据库 `oceanweb` 已存在且 `likangda@localhost` 用户具备 DDL/DML 权限
4. 用户具备访问外部 AI 服务与阿里云服务的网络出口

## 三、功能需求

### 3.1 用户认证与权限管理

#### FR-AUTH-01 用户注册
- **输入**：用户名、密码（确认密码）
- **处理**：用户名唯一性校验；密码 BCrypt 加密后写入 `user` 表，默认角色 `ROLE_USER`
- **输出**：注册成功提示，跳转登录页；用户名已存在时返回错误提示

#### FR-AUTH-02 用户登录
- **输入**：用户名、密码
- **处理**：校验用户名存在 + BCrypt 密码比对；成功后签发 JWT（有效期 100 天）
- **输出**：返回 JWT token 与用户信息（username、role）；前端持久化到 localStorage
- **异常**：用户名不存在或密码错误返回 401

#### FR-AUTH-03 当前用户信息
- **接口**：`GET /api/auth/me`（需登录）
- **处理**：解析 JWT 获取用户标识，从数据库查询最新角色
- **用途**：前端路由守卫在刷新页面时校验 token 有效性并刷新角色，防止 localStorage 失效后误入管理后台

#### FR-AUTH-04 权限控制
- **接口级**：Spring Security 配置 `/api/admin/**` 要求 `ROLE_ADMIN`
- **路由级**：前端路由 `meta.requiresAuth` 与 `meta.requiresAdmin` 守卫
- **特殊**：JWT role claims 不被信任，每次请求由 `JwtAuthenticationFilter` 查询 DB 获取真实角色
- **循环依赖处理**：`JwtAuthenticationFilter` 注入 `UserService` 时使用 `@Lazy` 注解

### 3.2 海洋生物物种管理

#### FR-SPEC-01 物种分类结构
- 物种分为三大类：鱼类（`fish_species`）、鲸类/哺乳动物（`whale_species`）、无脊椎动物
- 分类字段：纲（Class）、目（Order）、科（Family）、属（Genus）、学名（scientificName）
- 鲸类默认 `fishClass = "哺乳纲"`

#### FR-SPEC-02 物种 CRUD（管理后台）
- **接口**：`/api/admin/species/**`（需 `ROLE_ADMIN`）
- **功能**：
  - 分页查询三类物种，支持按名称、分类模糊检索
  - 新增物种（含图片上传至 OSS）
  - 更新物种信息
  - 删除物种（含 OSS 图片清理）
- **数据**：图片存储于阿里云 OSS，DB 仅存 URL

#### FR-SPEC-03 物种检索（前台）
- **接口**：`/api/species/**`（公开免认证）
- **功能**：
  - 列出全部物种
  - 按纲/目/科过滤
  - 综合查询：跨鱼/鲸/无脊椎三表统一检索
- **输出**：物种名称、分类、描述、图片 URL

#### FR-SPEC-04 分类树构建
- **接口**：`GET /api/species/taxonomy-tree`
- **处理**：使用 Java Stream 构建 **纲 → 目 → 科 → 物种列表** 的三层嵌套 Map 树
- **用途**：前端海洋图谱可视化渲染

### 3.3 智能海洋生物识别

#### FR-REC-01 图像识别请求
- **接口**：`POST /ai/recognize`（需登录，接收 `multipart/form-data`）
- **输入**：图片文件（≤4MB，`image/*` 类型）
- **流程**：
  1. 校验图片大小与类型
  2. 调用 **通义千问 VL（qwen-vl-max）** 识别，返回 `{isMarine, name, category}`
  3. 非海洋生物 → 返回提示并引导用户
  4. 是海洋生物 → 依次查询 `fish_species` / `whale_species` / `invertebrate` 三表
- **输出**：
  - DB 命中：返回 DB 权威记录，`source: "database"`
  - DB 未命中：调用 **通义千问 LLM（qwen-max）** 生成结构化物种信息，`source: "ai"`

#### FR-REC-02 数据源标识
- 前端须区分显示数据来源：`database`（数据库权威）/ `ai`（AI 生成兜底）
- 非海洋生物图片须给出友好警告提示

### 3.4 AI 智能对话

#### FR-AI-01 流式文本对话
- **接口**：`GET /ai/chatStream`（需登录，SSE）
- **输入**：用户消息文本
- **处理**：
  - 通过 `ai4j` 库调用 **DeepSeek（deepseek-chat）**
  - 使用 `SseEmitter` 实时推送 chunk
  - 自定义 `wrappedListener` 边转发边解析 `delta.content` 累积，SSE 完成后整体存入 MongoDB
- **输出**：SSE 流式响应；历史记录持久化到 MongoDB `chat_history` 集合

#### FR-AI-02 多模态对话
- **接口**：`POST /ai/chatWithImage`（需登录）
- **输入**：文本消息 + 图片文件
- **处理**：
  1. 图片上传至 MinIO，获取持久化 URL
  2. 调用 **通义千问 VL** 视觉模型作答
- **输出**：AI 回复文本；历史记录 `type: multimodal`，图片以 MinIO URL 持久化（不使用本地 data URL，避免跨会话丢失）

#### FR-AI-03 历史记录管理
- **接口**：`GET /ai/history`、`DELETE /ai/history`
- **数据**：MongoDB 按 `userId` 隔离
- **上下文构建**：`ChatHistoryService.buildContextText` 按 userId 拉取历史构建上下文，实现跨会话记忆

#### FR-AI-04 系统提示词
- 提示词文件：`src/main/resources/prompts/knowledge.txt`（海洋知识库）
- 通过 `PromptLoader` 加载并注入到 LLM 调用上下文

#### FR-AI-05 前端对话体验
- 用户消息显示在右侧、AI 回复显示在左侧
- 发送按钮根据输入状态切换图标：有输入/有图片时显示 `sendButton.png`，无输入时显示 `sendButton1.png`
- 集成 **语音朗读（TTS）** 与 **语音录制输入**
- 热门问题推荐换批
- 清空历史会话功能

### 3.5 科普视频点播

#### FR-VID-01 视频列表（前台）
- **接口**：`GET /api/videos`（需登录，分页）
- **参数**：`page`、`size`、`category`（科普视频 / 记录片段）
- **处理**：
  - 仅返回 `status = 1` 的上架视频
  - 列表查询时自动检查前 6 条缺封面/时长的视频，从 VOD `GetVideoInfo` 拉取首帧封面并回写 DB（单次限流避免 VOD API 过载）
- **输出**：视频 ID、标题、分类、封面 URL、时长、创建时间
- **前端**：`VideoList.vue` 展示卡片网格、分类筛选、分页

#### FR-VID-02 视频播放
- **接口**：`GET /api/videos/{id}/play-info`
- **处理**：
  - 调用 `GetVideoPlayAuth` 获取 `playAuth`，调用 `GetPlayInfo`（`OutputType=cdn`）获取播放地址
  - 视频转码中（Status=Transcoding）返回 **HTTP 409** + 友好提示
- **前端**：`VideoPlay.vue` 使用 Aliplayer
  - **优先** `vid + playauth` 模式：Aliplayer 自动选择切片格式与自适应码率
  - 仅在确认存在 m3u8 流时指定 `format: 'm3u8'`，避免无 m3u8 时报错
  - 兜底1：HLS 切片地址直链
  - 兜底2：mp4 直链
  - 收到 409 时**自动重试**：每 10s 一次，最多 10 次

#### FR-VID-03 视频管理（后台）
- **接口**：`/api/admin/videos`（需 `ROLE_ADMIN`）
- **功能**：
  - 分页查询所有状态视频（支持标题模糊、分类筛选）
  - 上传视频到 VOD（含**实时进度显示**：百分比、已传/总字节、上传速度、阶段提示）
  - 更新视频标题/描述/分类
  - 删除视频（VOD + DB 双删）
- **前端**：`VideoAdmin.vue`

### 3.6 海洋图谱与统计可视化

#### FR-VIS-01 分类树图谱

### 3.7 互动娱乐

## 四、非功能需求

### 4.1 性能需求
| 指标 | 要求 |
|---|---|
| 接口响应时间 | 普通查询 < 1s，分页查询 < 2s |
| AI 识别响应 | VL 识别首字节响应 < 10s（依赖外部 API） |
| AI 流式对话 | SSE 首字节响应 < 3s，chunk 间隔 < 500ms |
| 视频播放 | HLS 切片首帧加载 < 3s，转码完成后无卡顿 |
| 视频上传进度 | 进度回调延迟 < 500ms，实时显示百分比/速度 |
| 列表封面补全 | 单次请求最多检查 6 条，避免拖慢列表接口 |
| 并发 | 支持 50 并发用户同时在线 |

### 4.2 安全需求
1. 密码 BCrypt 加密存储，禁止明文
2. JWT 静态密钥，有效期 100 天
3. JWT role claims 不被信任，每次请求查 DB 获取真实角色
4. Spring Security STATELESS 会话
5. `/api/admin/**` 强制 `ROLE_ADMIN` 权限校验
6. 前端路由守卫刷新时调 `/api/auth/me` 校验 token
7. 401/403 错误友好处理，避免泄露后端细节
8. 文件上传校验大小（≤4MB）与类型（`image/*`）
9. MinIO bucket 配置公共读策略但限制写权限

### 4.3 可靠性需求
1. AI 服务调用失败须降级兜底（如识别失败返回提示而非 500）
2. VOD 转码中返回 409 + 自动重试机制
3. VOD 查询失败不影响视频列表整体返回
4. 单条 VOD 封面查询失败静默跳过
5. SSE 流式对话失败时给出明确错误提示
6. MongoDB 聊天历史只存 `delta.content`，避免存原始 JSON chunk导致乱码

### 4.4 可维护性需求
1. 后端模块分层清晰：Controller / Service / Mapper / Entity
2. MyBatis-Plus 3.5.3.1 与原生 MyBatis 共存，Mapper XML 中使用 `SELECT *` 避免漏列
3. Knife4j API 文档自动生成，路径 `/doc.html`
4. 所有 OkHttp 模块版本对齐 4.12.0（core / logging-interceptor / sse）
5. 百度 SDK 4.16.22 排除所有 JavaCV/JavaCPP/OpenCV/Tesseract/FFmpeg 原生库
6. 配置项集中管理于 `application.yml`

### 4.5 兼容性需求
1. 现代浏览器：Chrome / Edge / Firefox 最新版
2. Spring Boot 2.6+ 与 Knife4j 兼容：`spring.mvc.pathmatch.matching-strategy: ant_path_matcher`
3. MinIO 8.5.3 强制 OkHttp 4.x
4. ai4j-spring-boot-starter 1.3.0 配置前缀为 `ai4j`（非 `ai`）

### 4.6 可扩展性需求
1. AI 服务统一通过 `ai4j` 工厂调用，便于切换 LLM 供应商
2. 物种分类按生物分类学层级设计，支持后续新增门类
3. 视频分类支持扩展（当前为科普视频/记录片段）

### 8.3 已知约束与规避方案
1. Spring Boot WelcomePageHandlerMapping 回退到 index.html 会导致 API 文档返回 HTML，须显式配置静态资源映射
2. Vite 代理 `/images` 到后端时若后端未运行会 ECONNREFUSED，应直接由 `public` 目录服务静态图片
3. 百度 SDK 缺少 tesseract-windows-x86_64.jar 会导致 Tomcat JarScanner 警告
4. ai4j 1.3.0 传递依赖 okhttp-sse 3.14.9，须显式声明 4.12.0 对齐
5. VOD 转码未启用 HLS 模板时仅能播放 mp4，大视频会卡顿

### 8.4 验收标准
1. 用户可完成注册、登录、退出，刷新页面 token 仍有效
2. 管理员可登录后台执行物种与视频 CRUD
3. 上传海洋生物图片可触发 VL 识别，返回 DB 或 AI 生成的物种信息
4. AI 对话支持流式输出、图片附件、语音朗读、历史记录
5. 视频上传显示实时进度，转码完成后列表页自动回填首帧封面
6. 视频播放优先 HLS 切片，转码中返回 409 + 自动重试
7. 海洋图谱可视化正确渲染三层分类树
8. API 文档 `/doc.html` 可正常访问在线调试
